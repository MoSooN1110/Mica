# 09. 品質仕様 — 性能・安全性・信頼性・エラー処理・ログ・セッション

対象: 非機能要件全般。

---

## 1. 性能

エンジニアリング目標として扱う(CIで絶対時間のみを合否基準にしない。ベンチマークの回帰率を併用する)。

| 項目 | 目標 |
|---|---|
| 起動から初回描画 | 通常のワークスペースで200ms未満、体感即時 |
| キー入力から画面反映 | 通常のファイルで16ms以内 |
| 1万ファイルのツリー初期表示 | 500ms未満(以降は遅延走査) |
| Git status更新 | 非ブロッキング(UI停止ゼロ) |
| 診断描画 | 可視行数に比例(ファイル全体サイズに比例させない) |
| 大きなファイル | 大容量モードへ移行して劣化許容、クラッシュ不可 |

原則:

- ファイルツリー走査、検索、Git、構文解析、LSP、PTYをUIスレッドで実行しない
- 検索結果・診断は逐次表示する
- 入力イベントごとにプロジェクト全体の再スキャンをしない
- 不可視領域を毎フレーム全面再計算しない
- 描画ホットパスでのアロケーションを避ける(テーマ参照、行レイアウトのキャッシュ)

## 2. 安全性(データ保護)

- 未保存内容を暗黙に破棄しない
- 外部変更で編集中の内容を暗黙に上書きしない([03_workspace.md](03_workspace.md))
- ワークスペース外のファイルへの削除・移動を防ぐ(パス正規化と境界検証)
- シンボリックリンク経由の操作は実対象を明示する
- 破壊的操作は確認必須:
  - 未保存バッファを閉じる
  - ファイル削除、非空ディレクトリ削除
  - Git restore / discard
  - 未保存内容のディスク版での置換
  - 複数ファイルへの一括破壊操作
- 保存は一時ファイル+renameの安全な置換を基本とする([02_editor.md](02_editor.md))
- 外部コマンドをシェル文字列連結で実行しない

## 3. 信頼性

- ファイル監視イベントの欠落を想定し、手動更新を常に提供する
- Git状態はキャッシュのみを真実とせず、操作前に再検証する
- 端末サイズ変更・端末切断(SIGHUP)に耐え、切断時は可能な限り状態を保存する。Herdrのデタッチ/リアタッチ(ローカルおよび`--remote`のSSH経由を含む)はこの要件を実際に発生させる主要な経路であり、リアタッチ後の再描画・サイズ再同期が正しく行われること
- panic時に端末状態(raw mode、alternate screen、マウス)を復元する
- 起動時に前回の異常終了を検出し、復旧を提案できる
- 子プロセス(LSP、Git、シェル)を終了時に確実に回収する

## 4. エラー処理

- パニックを利用者向けの制御フローに使わない。回復可能な失敗は`Result`で表現する
- 編集内容を失う可能性がある場合は処理を中断する(進めない方へ倒す)
- エラーはステータスバー通知またはダイアログで表示し、詳細はログとOutputパネルへ記録する
- Git・外部プロセスのエラーでは実行コマンド、終了コード、stderrを保持する
- 権限エラーと不存在エラーを区別して表示する

## 5. ログと診断情報

- `tracing`を利用する。端末画面へ生ログを出さない
- ファイルログは既定で無効、`--log-file`と設定で有効化。ログレベルは設定可能
- パスやファイル内容を過剰に記録しない(内容そのものは記録しない)
- バグ報告向けの環境情報出力コマンドを用意する:

```text
mica version / rust target / terminal type ($TERM) / color capability /
workspace size / git backend / enabled language parsers & servers /
config paths / last panic summary
```

## 6. セッションと復旧

1.0要件:

- 記録: 開いていたワークスペース、ファイル、タブ順・ピン留め、アクティブタブ、カーソル位置、サイドバー・パネルのサイズと表示状態
- 未保存バッファをスワップ/ジャーナルから復旧可能にする
- 正常終了と異常終了を区別する
- 復旧データは利用者の判断で安全に破棄できる
- セッションデータの置き場所はXDG準拠(`~/.local/state/mica/`または`~/.local/share/mica/`)
- ワークスペースごとにセッションを分離する

復旧フロー:

- 異常終了後の起動時に復旧可能な未保存バッファを提示し、復旧 / 破棄 / 後で決める、を選べる
- 復旧の選択を保留しても通常の編集を開始できる
