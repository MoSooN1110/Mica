# 05. 統合ターミナル仕様

対象: 下部パネルのTerminalタブ。実PTYを使った統合ターミナル。

---

## 1. 原則

キャプチャしたstdoutでターミナルを偽装しない。統合ターミナルは実PTYを所有し、本物の端末として振る舞う。

## 2. 必須機能

- PTYの生成と所有(`portable-pty`等)
- 設定されたシェル(既定: `$SHELL`、フォールバック`/bin/bash`)の起動
- ANSI / VTエスケープシーケンスの解釈と描画(`alacritty_terminal`、`vte`等のVT互換実装を利用)
- パネルサイズ変更へのPTYリサイズ追従(SIGWINCH相当)
- 対話シェル(bash、zsh、fish)の通常利用
- フルスクリーンTUIプログラム(`lazygit`、`htop`、`vim`等)の動作
- スクロールバックバッファ(行数は設定可能)
- コピー(スクロールバック内の範囲選択 → OSC 52 / 内部クリップボード)と貼り付け(bracketed paste)
- 256色およびTrue Colorのパススルー
- シェル終了の検知と表示(自動でパネルを閉じない)

## 3. セッション

- 1.0では最低1セッション。複数の名前付きセッション(タブ内タブまたはリスト切り替え)を目標とする
- セッションごとに独立したPTY・スクロールバックを持つ
- Mica終了時は子プロセスへ適切にシグナルを送り、確実に回収する(ゾンビを残さない)
- 実行中のプロセスがある状態でMicaを終了する場合は確認する

## 4. 入力とフォーカス

- ターミナルにフォーカスがある間、キー入力は原則すべてPTYへ送る
- 予約キー(既定: `` Ctrl+` ``のパネル切り替え等、最小限)のみMicaが横取りする。予約キーは設定で変更可能にする
- 予約キー自体をターミナルへ送るためのエスケープ手段を用意する

## 5. 実行モデルと性能

- PTY I/OはUIスレッド外で処理し、出力はイベントとしてまとめて描画へ反映する
- 大量出力(`yes`、ビルドログ等)でUI全体の応答性を落とさない。フレームごとに全スクロールバックを再描画しない
- 出力の取りこぼし・順序入れ替わりを起こさない

## 6. 環境

- 作業ディレクトリはワークスペースルートで開始する
- `TERM`は互換性の高い値を設定する(実装で採用したVT実装に合わせ、`xterm-256color`等)
- Micaが内部で使う環境変数を子シェルへ漏らさない(必要最小限のみ設定する)
