## 2. プロダクト定義

Micaは、Linuxターミナル上で動作するRust製の軽量IDEである。VS Code風の画面構成と操作感——アクティビティバー、Explorer/Source Controlを切り替えるサイドバー、タブ付きエディタ、Problems/Output/Terminalを持つ下部パネル——を、GUIエディタより軽く速く、ターミナルの中で提供する。

主要な利用シナリオは以下である。

- Windows Terminal + WSL2上での日常開発
- ネイティブUbuntuのターミナル上での日常開発
- SSH接続先のリモートマシンでの開発(Mica自体をリモート側で起動する)
- tmux等のターミナルマルチプレクサ内での利用
- Herder(コーディングエージェントとターミナルウィンドウのオーケストレータ)が管理する1ウィンドウとしての動作

主たる利用者は人間の開発者だが、コーディングエージェント等の外部プロセス——とりわけHerderが管理するエージェント——が同じワークスペースを並行して変更することを設計の前提とする。外部変更の検知と未保存変更の保護は、付加機能ではなく中核要件である。

## 3. 目標・非目標

### 3.1 体験目標

- 起動から編集開始まで待たされない軽さ(目標値は[09_quality.md](09_quality.md))
- VS Codeから来た利用者が、説明なしで画面構成と基本操作を理解できる
- すべての主要操作がキーボードだけで完結し、同じ操作がマウスでも自然に行える
- Git中心のワークフロー(変更確認 → 差分レビュー → stage → commit → push)がエディタ内で完結する
- コードの問題(コンパイラ、リンター、LSP)が、コード上の下線とProblemsパネルの両方で即座に見える
- 実PTYを使った統合ターミナルで、シェルや`lazygit`等のフルスクリーンTUIがそのまま動く
- 低グレアで洗練されたダークテーマ。ただしSSH越しやWSLでも軽快に動作する描画コスト
- 日本語を含むUTF-8テキストを破壊せず編集・表示できる

### 3.2 非目標(1.0)

以下は明示的に仕様へ追加されない限り実装しない。

- デバッガー(DAP)
- 拡張マーケットプレイス、プラグインABI
- リアルタイム共同編集
- エディタ内蔵のリモートSSHトランスポート(SSH先でMica自体を起動する運用でカバーする)
- ノートブック
- 複数カーソル編集(ただし選択モデルは将来の複数選択へ拡張可能に設計する)
- リファクタリング支援、semantic tokens、完全なスニペットエンジン
- 完全なVim互換(専用モードとして明示的に仕様化されない限り)
- Git rebase / merge / cherry-pick / stash の専用UI、履歴グラフ、高度なコンフリクト解決UI
- 複数ワークスペースの同時管理

## 4. 想定ユーザーと利用形態

### 4.1 主利用者

- Linux(WSL2を含む)上で開発するソフトウェア開発者
- GUIエディタより軽量なプロジェクト編集環境を求める利用者
- SSH先やターミナルマルチプレクサ上で作業する利用者
- コーディングエージェントと同じワークスペースを共有し、その変更をレビューする開発者

### 4.2 利用形態

- ローカルまたはSSH先のターミナルから`mica <path>`で起動する
- Herderの1ウィンドウとして`mica <path>`で起動される
- 対象フォルダをワークスペースとして開き、プロジェクト全体を扱う
- 人間が編集しつつ、別プロセス(エージェント、ビルド、フォーマッタ等)が同じファイルを更新する
- Git差分をエディタ内で確認し、変更をレビューして採用・破棄する

### 4.3 Herderとの責務分界

MicaはHerderの1ウィンドウとしても動作する。単独起動とHerder内起動で機能差を作らない。

Herderの責務(Micaは実装しない):

- エージェントの起動・停止・監視、作業割り当て
- エージェントとの対話、エージェント実行ログの管理・表示
- ターミナルウィンドウ・ペインの配置、セッション編成

Micaの責務:

- ワークスペースの表示・編集・ファイル操作
- Git差分のレビューとGit操作
- 統合ターミナル、診断表示

境界原則:

- MicaはHerderの内部状態を管理・参照しない。Herderの存在を前提とした分岐を持たない
- HerderはMicaの内部バッファを直接操作しない
- 連携はCLI起動引数([07_config_cli.md](07_config_cli.md))と、将来の明示的なコマンド境界(`micactl`等、[08_architecture.md](08_architecture.md) §7)で行う。画面座標や疑似キー入力に依存した連携を前提としない
- Herder管理下のエージェントによるワークスペース変更は「外部変更」として検知・保護の対象とする([03_workspace.md](03_workspace.md))
- Herderによるペインのリサイズ・再アタッチに耐える(端末サイズ変更耐性は[01_ui.md](01_ui.md) §1.5)
- Herderがセッションを保持していても、Micaプロセス自体のクラッシュ・再起動からの復旧はMica自身の責務とする([09_quality.md](09_quality.md) §6)

## 5. マイルストーン

機能は以下の順で段階的に実装する。各マイルストーンは単体で日常利用に耐える状態を保つ。

### M1: コアエディタ

- ワークスペースを開く、ファイルツリー、ファイル操作(作成・削除・改名・移動)
- タブ付きエディタ、保存、Undo/Redo、UTF-8と日本語
- バッファ管理と競合保護の基盤、外部変更検知
- コマンドパレットとコマンドID層、キーマップ、設定ファイル
- ファジーファイル検索
- ダークテーマ、Tree-sitter構文ハイライト(Rust, Markdown, TOML程度から)

### M2: Gitと検索

- Git状態表示、ファイル/ハンク差分、stage / unstage / restore、commit
- branch一覧・切り替え・作成、push / pull / fetch
- ワークスペース全文検索
- セッション復旧

### M3: 統合ターミナル

- 実PTYによるターミナル、ANSI/VT解釈、リサイズ、スクロールバック
- 下部パネル(Terminal / Output)の完成

### M4: 診断とLSP

- 診断モデルとProblemsパネル、エディタ下線、コンパイラ・リンター出力の統合
- 最小LSPクライアント: diagnostics / hover / 定義ジャンプ / 補完
- 対応言語: C/C++, Rust, Python, JSON, Markdown

## 6. 1.0受け入れ条件

以下をすべて満たした時点で1.0とする。

1. Linuxターミナル(WSL2、ネイティブUbuntu、SSH先、tmux内、Herderの1ウィンドウ内を含む)で起動できる
2. フォルダをワークスペースとして開ける
3. アクティビティバーでExplorer / Source Control / Searchを切り替えられる
4. ファイルツリーをマウスとキーボードの両方で操作できる
5. ファイルの作成、削除、改名、移動ができる
6. 複数ファイルをタブで編集できる
7. 保存、Undo、Redoが動作する
8. 日本語を含むUTF-8テキストを破壊せず編集できる
9. ファジーファイル検索とワークスペース全文検索ができる
10. Git変更一覧、ファイル差分、ハンク差分を表示できる
11. stage、unstage、restore、commitができる
12. branchの一覧・切り替え・作成、push、pullができる
13. 統合ターミナルで対話シェルとフルスクリーンTUIが動作する
14. コンパイラ・リンター・LSP由来の診断が下線とProblemsパネルに表示される
15. C/C++, Rust, Python, JSON, MarkdownでLSPのhover・定義ジャンプ・補完が動作する
16. 外部ファイル変更を検知し、未保存変更と外部変更の競合でデータを失わない
17. 主要操作がすべてコマンドID経由で実行でき、コマンドパレットから呼び出せる
18. UIを停止させる重い同期処理が残っていない
19. 異常終了後に端末状態が復元され、基本的なセッション復旧ができる
20. True Colorと256色端末の両方で表示が破綻しない
21. 単体・統合・スナップショットテストが整備され、CIで通っている
22. `AGENTS.md`の実装規約に適合している

## 7. 用語集

| 用語 | 定義 |
|---|---|
| ワークスペース | Micaが開いている1つのルートフォルダとその配下 |
| バッファ | メモリ上のテキスト内容と編集履歴。ファイルと1対1とは限らない |
| ビュー | バッファに対する表示状態(カーソル、スクロール位置、選択) |
| タブ | エディタグループ内でビューを切り替えるUI要素 |
| ハンク | 差分の連続した変更ブロック |
| 診断 | コード上の問題(エラー、警告、情報、ヒント)の正規化された1件 |
| サイドバー | 画面左のExplorer / Source Control / Searchを表示する領域 |
| アクティビティバー | サイドバーの表示内容を切り替える最左列 |
| 下部パネル | Problems / Output / Terminalを表示する画面下部の領域 |
| 外部変更 | Micaプロセス以外(エージェント、git、ビルド等)によるワークスペースの変更 |
| Herder | 複数のコーディングエージェントとターミナルウィンドウを管理するオーケストレータ。Micaはその1ウィンドウとして動作できる |
