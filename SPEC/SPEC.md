## 2. プロダクト定義

Micaは、Linuxターミナル上で動作するRust製の軽量IDEである。VS Code風の画面構成と操作感——アクティビティバー、Explorer/Source Controlを切り替えるサイドバー、タブ付きエディタ、Problems/Output/Terminalを持つ下部パネル——を、GUIエディタより軽く速く、ターミナルの中で提供する。

主要な利用シナリオは以下である。

- Windows Terminal + WSL2上での日常開発
- ネイティブUbuntuのターミナル上での日常開発
- SSH接続先のリモートマシンでの開発(Mica自体をリモート側で起動する)
- Herdr(コーディングエージェントとターミナルウィンドウのオーケストレータ)が管理する1ウィンドウとしての動作

主たる利用者は人間の開発者だが、コーディングエージェント等の外部プロセス——とりわけHerdrが管理するエージェント——が同じワークスペースを並行して変更することを設計の前提とする。外部変更の検知と未保存変更の保護は、付加機能ではなく中核要件である。

## 3. 目標・非目標

### 3.1 体験目標

- 起動から編集開始まで待たされない軽さ(目標値は[09_quality.md](09_quality.md))
- VS Codeから来た利用者が、説明なしで画面構成と基本操作を理解できる
- すべての主要操作がキーボードだけで完結し、同じ操作がマウスでも自然に行える
- Git中心のワークフロー(変更確認 → 差分レビュー → stage → commit → push)がエディタ内で完結する
- コードの問題(コンパイラ、リンター、LSP)が、コード上の下線とProblemsパネルの両方で即座に見える
- 実PTYを使った統合ターミナルで、シェルや`lazygit`等のフルスクリーンTUIがそのまま動く
- 低グレアで洗練されたダークテーマ。ただしSSH越しやWSLでも軽快に動作する描画コスト
- 日本語を含むUTF-8テキストを破壊せず編集・表示できる

### 3.2 非目標(1.0)

以下は明示的に仕様へ追加されない限り実装しない。

- デバッガー(DAP)
- 拡張マーケットプレイス、プラグインABI
- リアルタイム共同編集
- エディタ内蔵のリモートSSHトランスポート(SSH先でMica自体を起動する運用でカバーする)
- ノートブック
- 複数カーソル編集(ただし選択モデルは将来の複数選択へ拡張可能に設計する)
- リファクタリング支援、semantic tokens、完全なスニペットエンジン
- 完全なVim互換(専用モードとして明示的に仕様化されない限り)
- Git rebase / merge / cherry-pick / stash の専用UI、履歴グラフ、高度なコンフリクト解決UI
- 複数ワークスペースの同時管理
- tmux等のターミナルマルチプレクサ内での動作保証(利用者は使用しないため、検証・対応の対象外とする)
- 英語・日本語以外のUIローカライズ、汎用的なi18nフレームワーク([01_ui.md](01_ui.md) §7)

## 4. 想定ユーザーと利用形態

### 4.1 主利用者

- Linux(WSL2を含む)上で開発するソフトウェア開発者
- GUIエディタより軽量なプロジェクト編集環境を求める利用者
- SSH先で作業する利用者
- コーディングエージェントと同じワークスペースを共有し、その変更をレビューする開発者

### 4.2 利用形態

- ローカルまたはSSH先のターミナルから`mica <path>`で起動する
- Herdrの1ウィンドウとして`mica <path>`で起動される
- 対象フォルダをワークスペースとして開き、プロジェクト全体を扱う
- 人間が編集しつつ、別プロセス(エージェント、ビルド、フォーマッタ等)が同じファイルを更新する
- Git差分をエディタ内で確認し、変更をレビューして採用・破棄する

### 4.3 Herdrとの責務分界

[Herdr](https://herdr.dev/)(バイナリ`herdr`)は「AIコーディングエージェントのためのターミナルワークスペースマネージャ」であり、実PTYベースのペイン・タブ・ワークスペース、セッションの永続化とデタッチ/リアタッチ、SSH経由のリモートアタッチ、JSON Socket API+CLI、エージェント状態の追跡を持つ、本物のターミナルマルチプレクサである。tmux/screenとは異なりMicaの利用者が実際に使用するツールであるため、対応が必要となる([SPEC.md](SPEC.md) §3.2でtmux等の非対応を明記しているのはHerdrとは別枠であることに注意)。

MicaはHerdrの1ペインで動作するプログラムの1つとして起動される(例: ユーザーがHerdr内のシェルから`mica .`を実行する、または`herdr pane run <pane_id> -- mica .`で起動する)。単独起動とHerdr内起動で機能差を作らない。

#### 4.3.1 責務分界

Herdrの責務(Micaは実装しない):

- 複数ペイン・タブ・ワークスペースの作成、分割、配置、フォーカス移動
- セッションの永続化、デタッチ/リアタッチ、SSH経由のリモートアタッチ
- エージェントの起動・状態追跡(idle/working/blocked)、エージェントとの対話

Micaの責務:

- 1ペイン内で完結するワークスペースの表示・編集・ファイル操作、Git差分のレビュー、統合ターミナル、診断表示

#### 4.3.2 レイヤーの区別

HerdrのペインとMicaの統合ターミナル([05_terminal.md](05_terminal.md))は別レイヤーであり、混同しない。

- Herdrは外側でペイン(プログラム単位)を多重化する。1ペインは通常「1つのフルスクリーンプログラム」を表示する
- Micaはその1ペインの中で動くプログラムであり、Mica自身が内部に持つ統合ターミナルパネルは、Herdrのペインとは独立した、Mica専有の入れ子のPTYである
- Micaは複数ペインへの分割やセッション管理をMica自身の機能として再実装しない(既存の非目標「複数ワークスペースの同時管理」はこの理由による)。複数ペインが必要な利用者はHerdr自体の分割機能を使う

#### 4.3.3 境界原則

- MicaはHerdrの内部状態(他ペインの内容、ワークスペース構成等)を管理・参照しない。Herdrの存在を前提とした分岐を持たない。Herdr環境変数(`HERDR_ENV`、`HERDR_PANE_ID`、`HERDR_TAB_ID`、`HERDR_WORKSPACE_ID`、`HERDR_SOCKET_PATH`)は存在すれば読み取ってよいが、機能の可否を左右してはならない
- HerdrはMicaの内部バッファを直接操作しない
- 連携はCLI起動引数([07_config_cli.md](07_config_cli.md))と、将来の明示的なコマンド境界([08_architecture.md](08_architecture.md) §7)で行う。画面座標や疑似キー入力に依存した連携を前提としない
- Herdr管理下のエージェントによるワークスペース変更は「外部変更」として検知・保護の対象とする([03_workspace.md](03_workspace.md))
- Herdrによるペインのリサイズ・zoom・デタッチ/リアタッチ(ローカルおよび`--remote`のSSH経由を含む)に耐える(端末サイズ変更耐性は[01_ui.md](01_ui.md) §1.5、信頼性は[09_quality.md](09_quality.md) §3)
- Herdrがセッションを保持していても、Micaプロセス自体のクラッシュ・再起動からの復旧はMica自身の責務とする([09_quality.md](09_quality.md) §6)

#### 4.3.4 キー入力とターミナル特性

- Herdrの既定キー操作はprefixキー(既定`ctrl+b`、設定変更可能)によるprefixモードで完結し、通常のチョード(`Ctrl+Shift+X`等)を素通しでフォーカス中のペインへ渡す。したがってWindows Terminal等と異なり、HerdrがMicaの既定キーバインドを奪うことは基本的にない。ただし利用者がHerdrの設定でprefix以外の直接キーバインドを追加した場合の衝突は起こりうるため、Micaのキーマップ変更機能([07_config_cli.md](07_config_cli.md))とコマンドパレットによる代替経路は必須のまま維持する
- Herdrは`$TERM`・カラー機能を素通しする(tmuxのような`TERM=screen-*`への書き換えは行わない)ことを確認済み。Micaの端末機能検出はこの前提で実装してよいが、値を過信せず実際の描画結果で検証する

#### 4.3.5 将来のHerdr連携(1.0対象外)

Herdrは`herdr pane report-metadata`等、ペインのタイトル・カスタムステータスをSocket API/CLI経由で外部から設定する機能を既に持つ。将来、Micaがコマンド層([08_architecture.md](08_architecture.md) §7)を通じて現在編集中のファイル・未保存状態・診断件数等をこの既存APIへ反映する統合は検討に値するが、1.0の要件ではない。独自の`micactl`を発明する前に、まずHerdr側の既存API再利用を検討すること。

## 5. マイルストーン

機能は以下の順で段階的に実装する。各マイルストーンは単体で日常利用に耐える状態を保つ。

### M1: コアエディタ

- ワークスペースを開く、ファイルツリー、ファイル操作(作成・削除・改名・移動)
- タブ付きエディタ、保存、Undo/Redo、UTF-8と日本語
- バッファ管理と競合保護の基盤、外部変更検知
- コマンドパレットとコマンドID層、キーマップ、設定ファイル
- ファジーファイル検索
- ダークテーマ、Tree-sitter構文ハイライト(Rust, Markdown, TOML程度から)

### M2: Gitと検索

- Git状態表示、ファイル/ハンク差分、stage / unstage / restore、commit
- branch一覧・切り替え・作成、push / pull / fetch
- ワークスペース全文検索
- セッション復旧

### M3: 統合ターミナル

- 実PTYによるターミナル、ANSI/VT解釈、リサイズ、スクロールバック
- 下部パネル(Terminal / Output)の完成

### M4: 診断とLSP

- 診断モデルとProblemsパネル、エディタ下線、コンパイラ・リンター出力の統合
- 最小LSPクライアント: diagnostics / hover / 定義ジャンプ / 補完
- 対応言語: C/C++, Rust, Python, JSON, Markdown

## 6. 1.0受け入れ条件

以下をすべて満たした時点で1.0とする。

1. Linuxターミナル(WSL2、ネイティブUbuntu、SSH先、Herdrの1ウィンドウ内を含む)で起動できる
2. フォルダをワークスペースとして開ける
3. アクティビティバーでExplorer / Source Control / Searchを切り替えられる
4. ファイルツリーをマウスとキーボードの両方で操作できる
5. ファイルの作成、削除、改名、移動ができる
6. 複数ファイルをタブで編集できる
7. 保存、Undo、Redoが動作する
8. 日本語を含むUTF-8テキストを破壊せず編集できる
9. ファジーファイル検索とワークスペース全文検索ができる
10. Git変更一覧、ファイル差分、ハンク差分を表示できる
11. stage、unstage、restore、commitができる
12. branchの一覧・切り替え・作成、push、pullができる
13. 統合ターミナルで対話シェルとフルスクリーンTUIが動作する
14. コンパイラ・リンター・LSP由来の診断が下線とProblemsパネルに表示される
15. C/C++, Rust, Python, JSON, MarkdownでLSPのhover・定義ジャンプ・補完が動作する
16. 外部ファイル変更を検知し、未保存変更と外部変更の競合でデータを失わない
17. 主要操作がすべてコマンドID経由で実行でき、コマンドパレットから呼び出せる
18. UIを停止させる重い同期処理が残っていない
19. 異常終了後に端末状態が復元され、基本的なセッション復旧ができる
20. True Colorと256色端末の両方で表示が破綻しない
21. 単体・統合・スナップショットテストが整備され、CIで通っている
22. `AGENTS.md`の実装規約に適合している

## 7. 用語集

| 用語 | 定義 |
|---|---|
| ワークスペース | Micaが開いている1つのルートフォルダとその配下 |
| バッファ | メモリ上のテキスト内容と編集履歴。ファイルと1対1とは限らない |
| ビュー | バッファに対する表示状態(カーソル、スクロール位置、選択) |
| タブ | エディタグループ内でビューを切り替えるUI要素 |
| ハンク | 差分の連続した変更ブロック |
| 診断 | コード上の問題(エラー、警告、情報、ヒント)の正規化された1件 |
| サイドバー | 画面左のExplorer / Source Control / Searchを表示する領域 |
| アクティビティバー | サイドバーの表示内容を切り替える最左列 |
| 下部パネル | Problems / Output / Terminalを表示する画面下部の領域 |
| 外部変更 | Micaプロセス以外(エージェント、git、ビルド等)によるワークスペースの変更 |
| Herdr | 複数のコーディングエージェントとターミナルウィンドウを管理するオーケストレータ。Micaはその1ウィンドウとして動作できる |
