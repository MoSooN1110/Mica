# Terminal Project Editor 仕様書

## 1. 文書情報

- 文書名: Terminal Project Editor 仕様書
- 対象: Linux向けRust製TUIプロジェクトエディタ
- ステータス: MVP仕様
- 想定実行環境: Linuxターミナル / Herder内の1ウィンドウ
- 実装言語: Rust

---

## 2. プロダクト定義

本プロジェクトは、Linuxターミナル上で動作し、人間とHerderで管理されるコーディングエージェントが、同一のワークスペースを安全かつ高速に編集・確認・レビューするための、Rust製プロジェクトエディタである。

本エディタは、エージェントの起動、監視、会話、タスク管理を行わない。これらはHerderの責務とする。

本エディタの責務は、ワークスペースの表示、テキスト編集、ファイル操作、Git差分確認、Git操作、外部変更検知、競合保護、変更レビューに限定する。

---

## 3. 目的

### 3.1 主要目的

- Linuxターミナル上で高速に起動し、即座に編集を開始できること
- フォルダをワークスペースとして開き、プロジェクト全体を扱えること
- 人間と外部エージェントが同じワークスペースを変更しても、変更を失わないこと
- Git差分を中心に、安全に変更を確認、採用、破棄できること
- Herderの1ウィンドウ内で安定して動作すること
- マウスとキーボードの双方で主要操作を完結できること

### 3.2 非目的

MVPでは以下を実装対象外とする。

- エージェント管理
- AIチャット
- エージェントへの指示送信
- エージェントの実行ログ管理
- 内蔵ターミナル
- デバッガー
- リアルタイム共同編集
- リモートSSH編集
- プラグインマーケット
- Git履歴グラフ
- Git rebase UI
- Git merge UI
- 高度なコンフリクト解決UI
- 完全なVim互換
- IDE相当のLSP統合
- 複数ワークスペース同時管理

---

## 4. 想定ユーザー

### 4.1 主利用者

- Linux上で開発するソフトウェア開発者
- Herderで複数のコーディングエージェントを管理する開発者
- GUIエディタより軽量なプロジェクト編集環境を求める利用者
- SSHやターミナルマルチプレクサ上で作業する利用者

### 4.2 利用形態

- Herderの1ウィンドウとして起動
- ローカルターミナルから単独起動
- 対象フォルダをワークスペースとして指定
- 人間が編集しつつ、別プロセスのエージェントが同じファイルを更新
- Git差分をエディタ内で確認し、変更をレビュー

---

## 5. Herderとの責務分界

### 5.1 Herderの責務

- エージェントの起動、停止、監視
- ターミナルウィンドウおよびペインの管理
- セッション管理
- エージェントごとの作業割り当て
- エージェントログの表示
- エージェントとの対話
- プロセス配置とワークスペース編成

### 5.2 本エディタの責務

- ワークスペースを開く
- ファイルツリーを表示する
- ファイルを編集する
- ファイルを作成、削除、移動、改名する
- Git状態を表示する
- Git差分を表示する
- Gitの基本操作を行う
- 外部変更を検知する
- 未保存変更と外部変更の競合を保護する
- 人間が変更をレビューするための画面を提供する
- HerderからCLIで起動可能にする

### 5.3 境界原則

- エディタはHerderの内部状態を直接管理しない
- Herderはエディタ内部のバッファを直接操作しない
- 連携が必要な場合は、CLIまたは明示的なコマンド境界を利用する
- 画面座標や疑似キー入力に依存した連携を前提としない

## 6. MVP機能一覧

### 6.1 ワークスペース

必須機能:

- フォルダをワークスペースとして開く
- 起動時にワークスペースルートを指定できる
- 相対パスは起動時のカレントディレクトリを基準とする
- `.git`ディレクトリを検出する
- `.gitignore`を尊重する
- シンボリックリンクを識別する
- 隠しファイル表示を切り替えられる
- ワークスペース外への移動を誤操作で行わない

起動例:

```bash
editor .
editor /path/to/project
editor src/main.rs
editor src/main.rs:42
editor src/main.rs:42:8
```

### 6.2 ファイルツリー

左側にワークスペースのファイルツリーを表示する。

必須機能:

- フォルダ展開、折り畳み
- ファイル選択
- ファイルを開く
- 新規ファイル作成
- 新規フォルダ作成
- ファイル削除
- フォルダ削除
- 名前変更
- 移動
- Git状態表示
- 外部変更時の自動更新
- マウスクリック操作
- キーボード操作
- コンテキストメニュー

削除時の要件:

- 削除対象を明示する
- ディレクトリ削除では確認ダイアログを表示する
- 未保存バッファに対応するファイルを削除する場合、警告する
- Git管理対象ファイルかどうかを表示する
- MVPではOSのゴミ箱連携を必須としない

### 6.3 エディタ

必須機能:

- テキスト表示
- テキスト入力
- カーソル移動
- 範囲選択
- コピー
- 切り取り
- 貼り付け
- 行番号表示
- 保存
- 名前を付けて保存
- Undo
- Redo
- 複数ファイルのタブ表示
- 未保存状態の表示
- 読み取り専用ファイルの表示
- ファイル末尾改行の保持
- 改行コードの保持または明示的変換
- UTF-8対応
- 日本語表示および入力
- タブ幅設定
- スクロール
- マウスによるカーソル移動
- マウスによる範囲選択
- 大きなファイルでUIを停止させない

初期段階では複数カーソルを実装しない。ただし、内部の選択モデルは将来的な複数選択へ拡張可能であること。

### 6.4 バッファ管理

ファイル、バッファ、ビュー、タブを別概念として扱う。

必須要件:

- 同一ファイルを重複してロードしない
- 未保存バッファを保持する
- ファイルが外部削除されても、未保存内容を即座に破棄しない
- 保存前後でUndo履歴を維持する
- 閉じる際に未保存変更を確認する
- バッファごとに変更世代を管理する
- ディスク上の最終確認時刻または内容ハッシュを保持する
- クラッシュ復旧用の最低限のジャーナルまたはスワップを設ける

### 6.5 ファジーファイル検索

必須機能:

- ワークスペース内のファイル名検索
- 最近開いたファイルの優先表示
- `.gitignore`準拠
- 隠しファイルの扱いを設定可能にする
- 候補選択時のプレビュー
- キーボードのみで操作可能
- コマンドパレットまたは専用ショートカットから起動可能

推奨ショートカット:

```text
Ctrl+P
```

### 6.6 ワークスペース全文検索

必須機能:

- 文字列検索
- 大文字、小文字の区別
- 正規表現検索
- `.gitignore`準拠
- 検索結果一覧
- ファイル名、行番号、該当行の表示
- 検索結果から対象位置へ移動
- 検索を中断可能
- UIスレッドをブロックしない

MVPでは置換機能を必須としない。

### 6.7 構文ハイライト

必須機能:

- Tree-sitter等による構文ハイライト
- 差分更新
- 大きなファイルで解析を中断または制限可能
- 未対応言語ではプレーンテキスト表示

初期対応候補:

- Rust
- Markdown
- JSON
- TOML
- YAML
- Shell
- JavaScript
- TypeScript
- Python

### 6.8 コマンドパレット

すべての主要操作はコマンドIDとして登録し、コマンドパレットから実行できること。

例:

```text
file.new
file.new_directory
file.rename
file.move
file.delete
editor.save
editor.save_as
editor.close
editor.undo
editor.redo
workspace.open_file
workspace.search
git.open_panel
git.open_diff
git.stage_file
git.unstage_file
git.stage_hunk
git.unstage_hunk
git.restore_file
git.restore_hunk
git.commit
view.toggle_file_tree
view.toggle_git_panel
```

要件:

- キーボード、マウス、コマンドパレットは同一のコマンド層を利用する
- UIイベントから直接ドメイン処理を呼ばない
- コマンドは一意な文字列IDを持つ
- 利用不可コマンドは理由とともに無効表示する
- 後から外部制御に利用できる設計にする

### 6.9 Git状態表示

必須表示:

- 現在のブランチ
- detached HEAD状態
- stagedファイル
- unstagedファイル
- untrackedファイル
- conflictedファイル
- ignoredファイルは既定で非表示
- ファイルごとの状態
- 変更数の概要

状態更新契機:

- 起動時
- ファイル保存時
- ファイル監視イベント時
- Git操作完了時
- 手動更新時
- 一定時間内のイベントはデバウンスする

### 6.10 Git差分表示

必須機能:

- working treeとindexの差分
- indexとHEADの差分
- ファイル単位の差分
- ハンク単位の差分
- 追加、変更、削除行の表示
- エディタ左端の差分マーカー
- 差分から対象行へ移動
- 大きな差分でもUIを停止させない

差分操作:

- ファイルをstage
- ファイルをunstage
- ハンクをstage
- ハンクをunstage
- ファイル変更をrestore
- ハンク変更をrestore
- 破壊的操作では確認する

### 6.11 Git commit

必須機能:

- staged変更の確認
- commit message入力
- 空メッセージ拒否
- commit実行
- 成功、失敗表示
- Gitフックの結果表示
- commit後の状態更新

MVPでは以下を対象外とする。

- amend UI
- interactive rebase
- cherry-pick UI
- stash UI
- push
- pull
- fetch
- remote管理

### 6.12 外部ファイル変更検知

人間以外のプロセスがワークスペースを変更することを前提とする。

必須機能:

- ファイル作成検知
- ファイル更新検知
- ファイル削除検知
- ファイル移動、改名検知
- ファイルツリー更新
- Git状態更新
- 開いているバッファの更新判定
- 大量イベントのデバウンス
- 一時ファイルのノイズ抑制

### 6.13 外部変更と未保存変更の競合

#### ケースA: バッファに未保存変更がない

- 外部変更を自動再読み込みする
- カーソル位置を可能な限り保持する
- スクロール位置を可能な限り保持する
- 状態バーに再読み込みを通知する

#### ケースB: バッファに未保存変更がある

自動上書きを禁止する。

利用者へ以下を提示する。

- ディスク版を確認
- 現在のバッファを保持
- 差分を確認
- ディスク版で置換
- 現在のバッファを別名保存

#### ケースC: ファイルが外部削除された

- バッファを保持する
- 削除済み状態を表示する
- 再作成、別名保存、閉じるを選択可能にする

### 6.14 変更レビュー

Git working treeを、エージェントを含む外部プロセスによる変更レビューの共通基盤として利用する。

必須機能:

- 変更ファイル一覧
- ファイル単位の差分確認
- ハンク単位の差分確認
- stage
- unstage
- restore
- レビュー中に通常編集へ移動
- 編集後に差分を再計算
- 変更の発生主体を推測して表示しない

本エディタは、変更が人間によるものかエージェントによるものかを保証しない。事実として確認できるGit差分のみを扱う。

- File Tree

フォーカスは常に1つの主要コンポーネントに属する。

必須要件:

- 現在のフォーカスが視覚的に判別できる
- Tabまたは設定可能なキーで移動できる
- マウスクリックで移動できる
- ダイアログ表示中は背後の操作を受け付けない
- フォーカス移動後も各コンポーネントの選択状態を保持する

## 8. 入力仕様

### 8.1 キーボード

すべての主要機能はキーボードのみで操作可能であること。

推奨初期キーバインド:

```text
Ctrl+P          ファイル検索
Ctrl+Shift+P    コマンドパレット
Ctrl+F          バッファ内検索
Ctrl+Shift+F    ワークスペース検索
Ctrl+S          保存
Ctrl+W          タブを閉じる
Ctrl+Z          Undo
Ctrl+Y          Redo
F2              名前変更
Delete          削除
Enter           開く、決定
Esc             閉じる、キャンセル
```

キーバインドは設定ファイルで変更可能にする。

### 8.2 マウス

必須機能:

- ファイルツリーのクリック
- フォルダ展開
- ファイルを開く
- タブ選択
- スクロール
- カーソル移動
- 範囲選択
- コンテキストメニュー
- パネル境界のドラッグ
- Git変更項目の選択
- 差分ハンクの選択

### 8.3 クリップボード

Linux環境差を考慮する。

- OSC 52対応を推奨
- WaylandまたはX11の外部コマンド連携は任意
- 内部クリップボードは必須
- 外部クリップボード失敗時も編集操作を継続可能にする

## 9. 設定

### 9.1 設定ファイル

推奨パス:

```text
~/.config/<editor-name>/config.toml
```

ワークスペース固有設定候補:

```text
<workspace>/.<editor-name>/config.toml
```

MVP設定項目:

```toml
[editor]
tab_width = 4
insert_spaces = true
line_numbers = true
mouse = true
auto_reload_unmodified = true
large_file_threshold_mb = 10

[workspace]
show_hidden = false
follow_symlinks = false
respect_gitignore = true

[git]
enabled = true
auto_refresh = true
confirm_destructive_actions = true

[ui]
file_tree_width = 28
git_panel_height = 12

[keymap]
"ctrl-p" = "workspace.open_file"
"ctrl-shift-p" = "command_palette.open"
"ctrl-s" = "editor.save"
```

### 9.2 設定エラー

- 起動不能にしない
- エラー箇所を表示する
- 不正な設定項目は既定値へフォールバックする
- 未知の項目は警告する

## 10. CLI仕様

### 10.1 起動

```text
editor [OPTIONS] [PATH]
```

### 10.2 想定オプション

```text
--line <N>
--column <N>
--readonly
--no-mouse
--config <PATH>
--log-file <PATH>
--safe-mode
--version
--help
```

### 10.3 PATH解釈

- ディレクトリ: ワークスペースとして開く
- ファイル: 親ディレクトリをワークスペースとして開き、対象ファイルを表示
- `file:line`: 指定行へ移動
- `file:line:column`: 指定位置へ移動
- 存在しないファイル: 親ディレクトリが存在する場合、新規バッファとして開く

## 11. エラー処理

### 11.1 原則

- パニックを利用者向け制御フローに使わない
- 編集内容を失う可能性がある場合は処理を中断する
- エラーは状態バーまたはダイアログに表示する
- 詳細はログへ記録する
- Gitエラーでは実行コマンド、終了コード、stderrを保持する
- 権限エラーと不存在エラーを区別する

### 11.2 破壊的操作

以下は確認を必須とする。

- 未保存バッファを閉じる
- ファイル削除
- 非空ディレクトリ削除
- Git restore
- 未保存内容をディスク版で置換
- 複数ファイルへの一括破壊操作

## 12. 非機能要件

### 12.1 性能

目標値:

- 通常ワークスペースで起動から初回描画まで100ms台を目標とする
- 主要入力に対する画面反映は16ms以内を目標とする
- ファイルツリー走査、検索、Git、構文解析をUIスレッドで実行しない
- 10MB超のファイルは大容量モードへ移行可能にする
- 10万ファイル規模でも段階的にツリーを表示できる設計とする
- 検索結果は逐次表示する
- Git差分はキャンセル可能にする
- 不可視領域を毎フレーム全面再計算しない

性能目標は開発環境に依存するため、CIで絶対時間だけを合否基準にしない。ベンチマークの回帰率も併用する。

### 12.2 安全性

- 未保存内容を暗黙に破棄しない
- 外部変更で編集中の内容を暗黙に上書きしない
- ワークスペース外の削除を防ぐ
- シンボリックリンク経由の操作対象を明示する
- Git restore等の破壊操作を確認する
- シェル文字列連結で外部コマンドを実行しない
- パスを信頼せず、正規化と境界検証を行う

### 12.3 信頼性

- ファイル監視イベント欠落を想定し、手動更新を提供する
- Git状態はキャッシュのみを真実としない
- 起動時に前回クラッシュを検出可能にする
- スワップまたはジャーナルから復旧可能にする
- 端末サイズ変更に耐える
- 端末切断時に可能な限り状態を保存する
- panic時に端末状態を復元する

### 12.4 Unicode

以下を区別する。

- バイトオフセット
- Unicode scalar value
- grapheme cluster
- ターミナル表示列
- 画面座標

必須テスト:

- 日本語
- 絵文字
- 結合文字
- 全角記号
- ゼロ幅文字
- タブ
- CRLF
- 長い日本語ファイル名
- Unicode正規化形が異なるファイル名

### 12.5 アクセシビリティ

- 色だけに状態を依存しない
- Git状態は記号と色の両方で表示する
- フォーカスは枠、記号、反転等で判別可能にする
- 低色数端末で利用可能にする
- 色テーマなしでも操作可能にする

```text
├── serde                設定、状態保存
├── toml                 設定ファイル
├── tracing              ログ
└── git2 または git CLI Git操作
```

Gitバックエンドは抽象化し、`git2`またはGit CLIを後から切り替え可能にする。

推奨方針:

- 読み取り頻度の高い状態取得は専用バックエンドへ隔離する
- 高度なGit操作を独自再実装しない
- 外部Git CLI利用時は引数配列で実行する
- Gitコマンド実行中もUIを停止しない

## 15. 状態管理

アプリケーションは単一の整合した状態を持つ。

```rust
struct AppState {
    workspace: WorkspaceState,
    buffers: BufferStore,
    views: ViewStore,
    git: GitState,
    search: SearchState,
    focus: FocusState,
    dialogs: DialogState,
    notifications: NotificationState,
    session: SessionState,
}
```

イベントは集約して処理する。

```text
Terminal Input
File Watcher
Git Task
Search Task
Syntax Task
Timer
Resize
Shutdown
    ↓
AppEvent
    ↓
Command / Update
    ↓
AppState
    ↓
Render
```

描画処理から状態を変更しない。

## 17. ログと診断

- `tracing`を利用する
- 既定ではファイルログを任意にする
- 端末画面へ生ログを出さない
- ログレベルを設定可能にする
- パスやファイル内容を過剰に記録しない
- panic hookで端末状態を復元する
- バグ報告向けに環境情報を出力できるようにする
