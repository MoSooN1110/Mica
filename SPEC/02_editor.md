# 02. エディタ仕様 — 編集・バッファ・Unicode・構文ハイライト

対象: テキスト編集機能、バッファ管理、Unicode取り扱い、構文ハイライト。

---

## 1. エディタ機能

### 1.1 必須機能

- テキスト表示・入力、カーソル移動、範囲選択
- コピー、切り取り、貼り付け
- Undo / Redo
- 保存、名前を付けて保存
- 行番号表示、アクティブ行の強調
- 行番号表示は設定およびコマンドでON/OFFできる
- 列の折り返し表示は設定およびコマンドでON/OFFできる
- 複数ファイルのタブ表示、未保存状態のタブ表示
- 縦・横スクロール
- エディターグループの左右2分割とグループ間フォーカス移動
- 読み取り専用ファイルの表示(編集不可の明示)
- マウスによるカーソル移動・範囲選択
- バッファ内検索(インクリメンタル、ヒットのハイライト、次/前へ移動)
- エディタ左端ガター: 行番号、Git差分マーカー、診断マーカー
- 診断の下線表示(端末が対応しない場合は色付き下線の代替表現)

### 1.2 テキストの取り扱い

- エンコーディングはUTF-8を正とする。UTF-8として不正なファイルは読み取り専用の警告付きで開くか、明示的な変換を提案する
- 改行コード(LF / CRLF)を保持する。変換は明示的な操作のみで行い、ステータスバーに現在の改行コードを表示する
- ファイル末尾の改行有無を保存時に保持する
- BOMを保持する(付け外しは明示操作)
- タブ幅と「タブ/スペース挿入」を設定可能にする
- 日本語の表示・入力・編集が正しく動作する(IMEからの貼り付け・入力を含む)

### 1.3 初期実装で対象外

- 複数カーソル。ただし内部の選択モデルは「選択のリスト」として設計し、将来の複数選択へ拡張可能にする
- 高度なコード折りたたみ
- 高度なVim互換

## 2. バッファ管理

ファイル、バッファ、ビュー、タブを別概念として扱う(定義は[SPEC.md](SPEC.md)の用語集)。

必須要件:

- 同一ファイルを重複してロードしない。同じファイルを複数タブで開いた場合は同一バッファを共有する
- 未保存バッファを保持する
- ファイルが外部削除されても、未保存内容を即座に破棄しない([03_workspace.md](03_workspace.md)の競合仕様)
- 保存の前後でUndo履歴を維持する
- 閉じる際に未保存変更を確認する
- バッファごとに変更世代(generation)を管理し、「ディスクと一致しているか」を判定できる
- ディスク上の内容ハッシュまたは最終確認時刻を保持し、外部変更判定に用いる
- クラッシュ復旧用の最低限のジャーナルまたはスワップを設ける([09_quality.md](09_quality.md))

### 2.1 保存の安全性

- 保存は「一時ファイルへ書き込み → fsync → rename」による安全な置換を基本とする
- シンボリックリンクやハードリンク、書き込み権限の都合で置換保存が不適切な場合は、上書き保存へフォールバックし、その旨を利用者が確認できるようにする
- 保存失敗(権限、ディスクフル等)でバッファ内容を失わない

### 2.2 大きなファイル

- 大きなファイル(既定10MB、設定可能)を開く際は大容量モードへ移行する
- 大容量モードでは構文ハイライト・LSP・差分装飾を制限し、編集と表示の応答性を優先する
- ファイルロードでUIスレッドをブロックしない

## 3. Unicode

### 3.1 区別すべき単位

実装は以下を明確に区別し、混同によるバグを型または命名で防ぐ。

- バイトオフセット
- Unicode scalar value(char)
- grapheme cluster(カーソル移動・削除の単位)
- ターミナル表示列(East Asian Width考慮後の幅)
- 画面座標(スクロール・折り返し適用後)

### 3.2 要件

- カーソル移動・削除はgrapheme cluster単位で行う
- 全角文字は表示幅2として扱い、行内の位置計算・マウスヒット判定・選択描画が一致する
- 絵文字(ZWJシーケンス、Variation Selectorを含む)でカーソル・削除・表示が破綻しない
- 結合文字、ゼロ幅文字、タブを正しく扱う
- 幅が曖昧な文字(East Asian Ambiguous)の扱いを設定可能にする
- 長い日本語ファイル名、Unicode正規化形が異なるファイル名を扱える

必須テストケースは[10_testing.md](10_testing.md)に定める。

## 4. 構文ハイライト

### 4.1 必須機能

- Tree-sitterによる構文ハイライト
- 編集に対する差分更新(全体再パースを毎キー行わない)
- 大きなファイルでは解析を中断・制限できる(大容量モードでは無効化)
- 未対応言語ではプレーンテキスト表示
- ハイライトはセマンティックトークン(theme.syntax_*)経由で着色する

### 4.2 対応言語

1.0での組み込み対応:

- Rust
- C / C++
- Python
- JSON / JSONC
- Markdown
- TOML
- YAML
- Shell(bash)
- JavaScript / TypeScript

言語の追加はTree-sitter文法の組み込みとハイライトクエリの追加で行える構造にする。

### 4.3 実行モデル

- 解析はUIスレッド外で行い、結果をイベントとして反映する
- 解析結果が間に合わないフレームでは、直前のハイライトまたはプレーン表示で描画を継続する(描画をブロックしない)
