# 01. UI仕様 — 画面構成・入力・テーマ

対象: 画面レイアウト、フォーカスモデル、キーボード・マウス・クリップボード入力、テーマとビジュアルデザイン。

---

## 1. 画面構成

### 1.1 基本レイアウト

VS Codeの画面構成を踏襲する。

```text
┌───┬─────────────────┬──────────────────────────────────────┐
│ A │ Sidebar         │ Editor Group                         │
│ c │                 │ ┌─ main.rs ─┬─ app.rs ──┬──────────┐ │
│ t │ (Explorer /     │ │           Editor                 │ │
│ i │  Source Control │ │                                  │ │
│ v │  / Search)      │ │                                  │ │
│ i │                 │ │                                  │ │
│ t │                 │ └──────────────────────────────────┘ │
│ y ├─────────────────┴──────────────────────────────────────┤
│   │ Bottom Panel: Problems │ Output │ Terminal             │
├───┴────────────────────────────────────────────────────────┤
│ Status Bar: branch │ diagnostics │ encoding │ Ln,Col │ msg │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 領域

| 領域 | 内容 |
|---|---|
| アクティビティバー | サイドバービューの切り替え。Explorer / Source Control / Search |
| サイドバー | 選択中のビューを1つ表示。表示・非表示を切り替え可能 |
| エディタグループ | タブバーとアクティブなエディタ |
| 下部パネル | Problems / Output / Terminalのタブ。表示・非表示を切り替え可能 |
| ステータスバー | ブランチ、診断件数、エンコーディング、改行コード、カーソル位置、通知履歴件数 |
| オーバーレイ | コマンドパレット、ファジー検索、ダイアログ、コンテキストメニュー |

エディターグループは左右に2分割できる。各グループは独立したアクティブタブを持ち、キーボードとマウスの双方でフォーカスを移動できる。これはMica内のバッファ表示分割であり、Herdrの外側ペイン分割やセッション管理を代替しない。

エディタタブには未保存マーカーと診断件数を表示する。ピン留めタブは左側にまとめ、閉じる操作から保護する。表示順とピン留め状態はセッションへ保存する。

### 1.3 サイドバービュー

- Explorer: ファイルツリー([03_workspace.md](03_workspace.md))
- Source Control: Git変更一覧と操作([04_git.md](04_git.md))
- Search: ワークスペース全文検索([03_workspace.md](03_workspace.md))

サイドバーはビューの切り替えであり、複数ビューの同時表示は行わない。幅はドラッグおよび設定で変更できる。

### 1.4 下部パネルタブ

- Problems: 診断一覧([06_diagnostics_lsp.md](06_diagnostics_lsp.md))
- Output: サブシステムのログ出力(Git、LSP、タスク等をソース別に切り替え)
- Terminal: 統合ターミナル([05_terminal.md](05_terminal.md))

高さはドラッグおよび設定で変更できる。

### 1.5 小さい端末への耐性

- 端末サイズ変更に追従し、パニックや描画破綻を起こさない(Herdrによるペインのリサイズ・再アタッチを含む)
- 幅・高さが不足する場合はサイドバー・下部パネルを自動的に畳むか、最小限の警告表示に切り替える
- 80x24でもエディタ単体での編集操作が成立すること

### 1.6 通知

- 保存完了、Git結果、外部ツール失敗等は操作を妨げないトーストとして表示する
- トーストは5秒後に消えるが、直近200件をレベル・UTC時刻付き履歴として保持する
- `Alt+N`、コマンドパレット、またはステータスバーの通知件数から履歴を開ける
- エラー・警告・情報はセマンティックテーマ色と文字記号の両方で区別する

## 2. フォーカスモデル

フォーカスは常に1つの主要コンポーネント(サイドバー、エディタ、下部パネルの各タブ、オーバーレイ)に属する。

必須要件:

- 現在のフォーカスが視覚的に判別できる(色のみに依存しない。枠・記号・反転等を併用)
- 設定可能なキーで領域間を移動できる
- マウスクリックでフォーカスが移動する
- ダイアログ・コマンドパレット表示中は背後の操作を受け付けない(モーダル)
- フォーカス移動後も各コンポーネントの選択状態・スクロール位置を保持する
- ターミナルにフォーカスがある間は、エスケープ手段(既定: `` Ctrl+` ``等の予約キー)を除きキー入力をPTYへ送る

## 3. キーボード入力

### 3.1 原則

- すべての主要機能はキーボードのみで操作可能であること
- キーバインドはコマンドIDへの割り当てとして設定ファイルで変更可能であること([07_config_cli.md](07_config_cli.md))
- キーはUIイベントとして直接処理せず、必ずコマンド層を経由する([08_architecture.md](08_architecture.md))

### 3.2 既定キーバインド

```text
── ファイル・検索 ──────────────────────────
Ctrl+P          ファジーファイル検索
Ctrl+Shift+P    コマンドパレット
Ctrl+F          バッファ内検索
Ctrl+Shift+F    ワークスペース全文検索(Searchビュー)
Ctrl+S          保存
Ctrl+W          タブを閉じる
Ctrl+Alt+P      アクティブタブのピン留め切り替え
Ctrl+Shift+PageUp / PageDown  タブを左右へ移動

── 編集 ────────────────────────────────
Ctrl+Z          Undo
Ctrl+Y          Redo
Ctrl+X / C / V  切り取り / コピー / 貼り付け

── ビュー切り替え ──────────────────────────
Ctrl+Shift+E    Explorer
Ctrl+Shift+G    Source Control
Ctrl+B          サイドバー表示切り替え
Ctrl+J          下部パネル表示切り替え
Ctrl+`          ターミナル表示切り替え
Ctrl+Shift+M    Problems
Alt+1 / 2 / 3   Explorer / Source Control / Search

── 汎用 ────────────────────────────────
F1              現在フォーカスで有効なキーバインド一覧
Alt+N           通知履歴
Tab / Shift+Tab フォーカス移動(ツリー・リスト間)
F2              名前変更
Delete          削除
Enter           開く・決定
Esc             閉じる・キャンセル
```

### 3.3 端末制約への対応

ターミナルではキーの届き方がGUIと異なるため、以下を要件とする。

- `Ctrl+Shift+英字`はWindows Terminal等のエミュレータ側ショートカットと衝突しうる。既定バインドが奪われた場合の代替(`Alt+数字`、コマンドパレット)を必ず用意する
- kitty keyboard protocol / modifyOtherKeysが利用可能な端末では拡張キー情報を利用してよいが、利用できない端末でも主要操作が成立すること
- 検証対象はWindows Terminal(WSL2)、ネイティブUbuntuの標準端末、Herdrの1ペインとしての動作の3つに限る。Herdrのキー特性は[SPEC.md](SPEC.md) §4.3.4を参照。tmux等の古典的なターミナルマルチプレクサ配下での動作は対象外とする([SPEC.md](SPEC.md) §3.2)
- 検出できない・衝突するキーの診断手段(キー入力の生イベント表示)をコマンドとして用意する

## 4. マウス入力

必須機能:

- ファイルツリーのクリック選択、ダブルクリックで開く、フォルダ展開・折り畳み
- タブのクリック選択とクローズ、ドラッグによる並べ替え、Ctrl+クリックによるピン留め切り替え
- エディタのクリックによるカーソル移動、ドラッグによる範囲選択
- スクロール(ホイール)
- アクティビティバー・下部パネルタブのクリック切り替え
- Git変更項目・差分ハンク・検索結果・Problems項目のクリック
- 右クリックによるコンテキストメニュー(ファイルツリー、タブ、エディタ)
- パネル境界のドラッグによるサイズ変更

マウスは補助手段であり、マウスなしでも全機能が利用できること。マウスサポートは設定およびCLIフラグで無効化できること(端末側の選択コピーを使いたい場合のため)。

---

## 5. クリップボード

Linux環境差を考慮する。

- OSC 52による端末経由コピーを第一とする(SSH越しでも動作するため)
- Wayland(`wl-copy`)またはX11(`xclip`/`xsel`)の外部コマンド連携は任意の補助手段とする
- 内部クリップボード(アプリ内コピー・ペースト)は必須とし、外部連携が失敗しても編集操作を継続できること
- 貼り付けはbracketed pasteに対応する

## 6. テーマとビジュアルデザイン

### 6.1 方針

- 視覚品質は第一級の要件である。ただし装飾のための描画コストは払わない
- 既定は低グレアでやや寒色寄りのダークテーマ。純黒ではなく、長時間の閲覧に耐える背景
- レトロ端末風ではなく、抑制の効いたモダンエディタの外観を目指す
- アニメーション、透過シミュレーション、フレーム毎のエフェクトは実装しない(点滅はターミナルカーソルのみ)

### 6.2 既定パレット

セマンティックロール(役割)を固定し、具体値はコントラスト検証後に調整してよい。

```toml
[theme.colors]
background      = "#10131A"  # エディタ地
surface         = "#151923"  # サイドバー・下部パネル
surface_raised  = "#1B202C"  # 入力欄・パレット・メニュー
border          = "#2A3140"
text            = "#D8DEE9"
text_muted      = "#8B95A7"
text_faint      = "#626C7D"
accent          = "#82AFFF"  # アクティブタブ・フォーカス・選択コマンド
selection       = "#26344D"
active_line     = "#171C27"
cursor          = "#E6EDF7"

syntax_keyword  = "#C792EA"
syntax_function = "#82AAFF"
syntax_type     = "#FFCB6B"
syntax_string   = "#C3E88D"
syntax_number   = "#F78C6C"
syntax_comment  = "#687487"
syntax_variable = "#D8DEE9"
syntax_constant = "#89DDFF"

git_added       = "#9ECE6A"
git_modified    = "#E0AF68"
git_deleted     = "#F7768E"
git_conflict    = "#FF9E64"

diagnostic_error   = "#FF6B81"
diagnostic_warning = "#EBCB8B"
diagnostic_info    = "#7AA2F7"
diagnostic_hint    = "#73DACA"
```

### 6.3 テーマアーキテクチャ

- ウィジェットに色をハードコードしない。すべての描画はセマンティックトークン経由で色を取得する
- 組み込みダークテーマを1つ持ち、利用者はTOMLファイルでテーマを差し替え・部分上書きできる
- テーマ値が欠けている場合は組み込み値へ安全にフォールバックする
- True Color対応端末では24bitで出力し、非対応端末では256色へ近似する。近似表を起動時に構築し、描画ホットパスでの割り当て・変換コストを避ける
- 色だけで意味を伝えない。Git状態・診断は記号(`M` `A` `D`、`E` `W`等)と色の両方で示す

### 6.4 視覚階層

- background: エディタ地 / surface: サイドバー・パネル / surface_raised: オーバーレイ、の3段で奥行きを作る
- borderは控えめな区切りに限定し、全パネルを明るい枠で囲まない
- 支配的なアクセント色は1色(accent)に限定する
- 彩度の高い色を広い面積に使わない
- フォーカス表示は2つ以上の信号(アクセント枠/下線+タイトルの明度差、カーソル状態等)を併用する
- 選択範囲は下の構文色が乗っても読めること

### 6.5 タイポグラフィ

フォントはターミナルエミュレータ側の設定に委ねる。Micaはフォントを同梱しない。

- 一般的なコーディング用等幅フォント(JetBrains Mono、Cascadia Code、Iosevka、IBM Plex Mono等)で崩れないこと
- ドキュメントでの推奨: Windows Terminal + WSLでは`JetBrains Mono`または`Cascadia Code`
- リガチャに意味を持たせない
- Unicode記号は保守的に使い、必ずASCIIフォールバックを持つ
- アイコンモードを3段階で提供する: `ascii` / `unicode`(既定) / `nerd_font`(任意)
- 罫線・矢印・`0/O` `1/l/I`等の紛らわしいグリフの描画をテーマ・フォント検証の対象とする
- 行の高さは端末1セルを前提とする

### 6.6 アクセシビリティ

- 状態を色だけに依存させない(記号・位置・反転を併用)
- 低色数端末(256色、16色)でも操作可能であること
- ハイコントラストモードと装飾削減モード(`reduced decoration`)を設定で提供する

## 7. UI言語(ローカライズ)

MicaのUI(メニュー、ダイアログ、コマンドパレット、ステータスバー、通知、エラーメッセージ等の画面まわりの文言)が対応する言語は**英語(`en`)と日本語(`ja`)の2つのみ**とする。編集対象ファイルの内容がどの言語・エンコーディングであっても扱えること([02_editor.md](02_editor.md) §3のUnicode要件)とは別の話であり、混同しない。

要件:

- 起動時の既定はシステムロケール(`LANG`/`LC_ALL`)から判定する。値が`ja`で始まれば日本語、それ以外はすべて英語にフォールバックする
- 設定([07_config_cli.md](07_config_cli.md))で`en` / `ja` / `auto`を明示指定できる
- UI文言はロケールごとのキー→文字列テーブルとして持つ、単純な仕組みで実装する。汎用的なi18nフレームワークや、任意言語を後付けできる拡張可能なプラグイン機構は導入しない
- 3つ目以降の言語追加、右から左(RTL)表示、ロケール依存の日付・数値書式は1.0は対象外とし、必要になった時点で仕様を更新してから対応する
- 言語切り替えは全文言に対して一括で行う(UI要素ごとに言語が混在する状態を作らない)
